# Changelog

## Unreleased

- On macOS, a switch onto an API key keeps the key readable when an oversized MCP credential falls back from Keychain to the credentials file. If the managed-key fallback cannot be saved, the switch fails before replacing the original OAuth credential.
- Dashboard fixes: Guide contents links keep the Guide open and scroll to the requested section, including after a reload. Native Claude Code update checks respect `autoUpdatesChannel` in the user's `settings.json` (including `CLAUDE_CONFIG_DIR`), and an update only reports success after the advertised version is verified as installed.
- `tycswap web`: two new tabs and more on the first page, for parity with the reference dashboard. **Settings** lists every `settings.json` key `tycswap config` knows with a control of its type, its range, default and current value, when a saved value takes effect, and *Save* / *Reset* per key (the editor used to be a card on the Auto tab, which keeps its live slider and links there). An **Updates** card and a header pill show a newer tycswap release and a newer Claude Code (from the installer Claude Code was set up with: native, npm, Homebrew or WinGet) and install either after a confirmation, with the installer's output; the server checks at start and every six hours, *Check now* checks again, and a failed check keeps what it knew and names the error. A **Guide** tab explains slots, windows, the threshold, getting started, switching, Auto, Settings, Sessions, Updates, Codex, the commands, troubleshooting and where the data lives. The Accounts card shows a callout when Claude Code is signed in with an account that is not stored yet and has *Add current login* as its main button (no confirmation); a notice above the accounts names an `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or `ANTHROPIC_BASE_URL` set in the server's environment or in Claude Code's `settings.json` (names only). The Accounts and Updates cards fold, remembered in `ui_prefs.json` under the backup root (`POST /api/ui/folded`). New routes: `POST /api/updates/check`, `POST /api/updates/apply`, `POST /api/ui/folded`, all behind the cookie and CSRF checks; the state document gains `currentLogin`, `authOverrides`, `updates` and `ui`. New packages `internal/ccversion` (the Claude Code check) and `update.Checker.Latest` (the release check that reports its error and refreshes the passive notice's cache).
- `tycswap tui` has a Settings screen: `c` on the dashboard, or the menu's "Settings…" row. It lists every `settings.json` key under its section with its effective value, a `(default)` marker when the key is not set, and the highlighted key's help, range or choices and default; `enter` edits the key with a control matching its kind (a bool toggles, a choice cycles, a number or string is typed), `u` resets it to its default, and every change is validated and written at once through the same path `tycswap config set` and `unset` use, one at a time. A refused value shows its message without writing; a saved threshold moves the dashboard's bar tick. The engine reads the file when it starts, so a change applies when the auto-switch screen is next opened (or `tycswap auto` next starts), and the screen says so; the auto-switch screen's `t` adjustment stays session-only and its hint now points at Settings. This lands beside the browser dashboard's Settings tab, which edits the same file (DESIGN A28).
- `tycswap config set` refuses `nan` for a number setting with the usual `must be between` message; it used to pass the range check and fail in the JSON encoder.
- Security: a switch no longer logs the MCP servers out. Claude Code keeps its MCP server OAuth tokens in `~/.claude/.credentials.json` under `mcpOAuth`, keyed by server rather than by account; a switch (manual, `--force`, auto, or `add --login --switch`) now writes the target account's stored credential with the live `mcpOAuth` carried over it, and `add`, the switch-time backup, the unclaimed stash, the active refresh write-back and `export` store or ship the account part only, so MCP logins neither flip with the account, go stale in a backup, nor travel in an export. `trustedDeviceToken` stays with the account. Rollback still restores the exact pre-switch bytes.
- An API-key seat no longer loses its key or its MCP logins. On such a seat Claude Code writes `~/.claude/.credentials.json` holding only the MCP server logins when one is signed in to; tycswap read that file as the live OAuth login, so a switch away stored it in the API-key slot in place of the key, the switch back cleared the key and left no working credential, `status` and `list` showed the account as `no credentials`, and `add` stored the MCP data as a new subscription account. A credentials file or Keychain item holding nothing but seat-wide keys (or `{}`) is now no login: the managed key behind it is the live credential for the switch-time backup, `add`, `export`, `status` and `list`, and with no key behind it a switch away refuses as for an empty credential. A switch onto an API-key account keeps the seat-wide keys in the credentials file (or Keychain item) instead of deleting it, as Claude Code's own move onto an API key does. `mcpOAuthClientConfig`, the client secret an MCP server was added with (`claude mcp add --client-secret`), is seat-wide too: it is carried over every switch and left out of every stored or exported credential like `mcpOAuth`; a stored credential's own copy of either key is never written live, and `import` and the legacy keyring migration store the account part only (DESIGN A29).
- An API-key slot the switch-time backup had already emptied before that fix (it holds `{}`, or only the MCP server logins or client secrets, and its key survives in `.prev`) is no longer switched to. tycswap took the stored text for an OAuth login, wrote it live and cleared the managed key, so `switch`, `switch --force`, the rotation, the dashboard and the auto-switch engine reported success over a seat left with no working credential, and `export` shipped the `{}` as the account's credentials. A stored credential holding nothing but seat-wide keys now counts as no stored credential: `switch <n>` stops with `Account-<n> has no stored credentials` before the live login or the managed key is written, the rotation and the auto-switch engine skip the slot, and `export` leaves it out (DESIGN A30).
- A direct activation onto an API-key account (`switch <n> --force`, a fresh machine, or a live login no slot holds) no longer loses the key. It wrote back the copy of `~/.claude.json` it had read before writing the credential, which dropped what the key write had just stored there: `primaryApiKey` and the key's approval. Outside the macOS Keychain the seat was left with no credential while the switch reported success. In the other direction, a `--force` from a live API key onto a subscription account left the old key in `~/.claude.json`. The activation now reads the file again after the credential write, as the normal switch does (DESIGN A29).
- `list` no longer prints an empty "Running instances:" heading when the only live IDE lock has no workspace folders. Paths are shortened to `~` only when the home directory is followed by a separator (`/home/xavier` is no longer `~avier` for home `/home/x`); Windows compares case-insensitively.
- `tycswap migrate` resumes an interrupted copy: a rerun copies what is missing, verifies byte for byte what is there, removes a leftover temp file, and refuses only when a path differs from the old store or is not from it. A rerun after a complete copy is a verified no-op.
- Hardening: atomic writers fsync the temp file and the directory, and config backups are written atomically. `settings.json` and `mappings.json` updates hold a lock (`.settings.lock`, `.mappings.lock`) so concurrent commands no longer lose each other's change. `go.mod` pins `toolchain go1.25.14`; `golang.org/x/mod` is raised to v0.40.0 (GO-2026-6179, GO-2026-6180; tycswap does not call the affected code); `make vuln` runs govulncheck.
- Security: strings from exports, APIs and other tools' files (emails, aliases, organization/workspace names, IDE paths) are printed without C0/C1/ESC control characters in `list`, `status`, the dashboard and the Codex commands; `--json` output carries them as stored. `env --shell pwsh` doubles U+2018–U+201B as well as `'`. `add --login` scrubs the auth override variables like `run`/`env`. `add-token` warns when the token is given on the command line, and the docs show the prompt and `-` instead. On Windows, `run` and `add --login` refuse cmd.exe metacharacters in arguments when `claude` is a `.cmd`/`.bat` shim.
- Security: every command refuses a store root not owned by the effective user, naming the path, and makes a root writable by group/other 0700 before it runs; when the mode does not change (a filesystem without POSIX modes, such as a Windows drive under WSL), it warns once on stderr and continues (POSIX). The store lock is opened without following symlinks and without truncation (0600). A stale Claude Code lock directory is broken by rename-then-remove with an age recheck, so two waiters can no longer both hold it; a lock found fresh after the rename is put back without replacing one a third waiter took meanwhile (`renameat2` with `RENAME_NOREPLACE` on Linux). Directories tycswap creates (credentials, `~/.claude`, export parents, lock dirs) are 0700 instead of 0777 before umask. The Claude and Codex HTTP clients no longer follow redirects (a 307 would have re-posted the refresh token); the Claude client caps success bodies at 1 MiB, requires a non-empty string `access_token` and 0 < `expires_in` < 1e7, and logs only the error code of a failed refresh, never the body.
- Security: an inactive account's token refresh (`list`, `status`, dashboard) now takes the store lock before the request, re-checks that the slot is still inactive with no live session, re-reads the backup, and refreshes only when its refresh token is unchanged, as the Codex side does; a concurrent switch or refresh can no longer be overwritten or have its token consumed. `run`/`env` no longer refresh a backup that shares its refresh token with the live login (slot is the current account, or the fingerprints match). `codex login` stores the live auth into its slot before codex replaces it.
- Security: `add` and `add --login` refuse a login whose email cannot name a file, since the email names the account's backup files (`a/../../../x` would name files outside the store): it must hold one `@` between a non-empty local part and domain, at most 254 bytes, and no whitespace, control character, `/`, `\` or `< > : " | ? *`; every real address, an apostrophe or a non-ASCII letter included, is accepted and stored under its raw name. `purge` applies the same check to every `sequence.json` email before it builds a path from one and refuses with the slot named. `import` keeps claude-swap's stricter address pattern for export files. `codex import` validates every row first (email, alias, accountKey) and refuses the file on a bad one; both imports store display fields without control characters.
- `tycswap migrate` copies a macOS Keychain item too large for the `security` command's stdin line (over about 2 KB, as the old tool stored through the command line) to the file tycswap reads for it instead of failing: `credentials/.creds-<n>-<email>.enc[.prev]`, `codex/credentials/<key>.json` or the session profile's `.credentials.json`, mode 0600; the report names the file. The legacy keyring migration does the same with the `.enc` file instead of retrying on every launch.
- Security: on macOS a Claude credential too large for `security -i`'s stdin line (over about 2 KB, reachable with `mcpOAuth` tokens) was passed to `security` on its command line, where `ps` shows it to every local user. The Keychain wrapper now refuses such a payload and the credential is stored in its 0600 file instead (backup `.enc`, `.enc.prev`, or the live `.credentials.json`); the Keychain stays in use for everything else.
- Security: `import` keeps only each account's `oauthAccount` from an export's `config` (a `--full` export included), so an export carrying `mcpServers`, allowed tools or hooks can no longer configure commands on the importing machine; an account without `oauthAccount` is refused. Members are matched exactly and the stored credentials are the bytes that were validated (a `CREDENTIALS` twin used to be stored instead); input over 8 MiB is refused. A switch with no live `~/.claude.json` writes `{"oauthAccount": …}` alone instead of the whole stored config, and a live `~/.claude.json` that exists but does not parse is an error for a switch and for `add-token` instead of being replaced by the few keys tycswap sets.
- `tycswap web [--port N] [--no-open] [--interval SECONDS] [--debug]` serves a browser dashboard on 127.0.0.1: Dashboard (accounts and their actions), Auto (a hosted auto-switch engine with its settings, Next best, quarantine and event log), and Sessions (running Claude Code sessions, including `run`/`env` profiles, with Stop). The printed URL carries a one-time token; redeeming it sets the port-scoped session cookie and hands the page its CSRF token in the redirect's URL fragment, so the browser tab that opened the URL is the only one that can drive the page (a reload keeps it, a new tab needs a fresh URL). Every API call needs cookie and token, mutations a same-origin request, and a foreign Host gets 421. Stop signals a session only after the process start time matches its session file. On Linux and macOS the launch token reaches the browser through a 0600 redirect page in a private directory, never a command line. Export and import stay on the command line; Claude accounts only for now.
- The auto-switch engine can retarget its model windows while it runs (`Engine.ApplyModels`), so the dashboard's *Count model limits* applies at once.
- Internal: JSON account listings carry `tokenStatus` when token status is asked for; it was ignored before. Build-time branding vars in `internal/brand` (see `docs/reference.md`, BUILD-TIME BRANDING).
- Security: Keychain service and account names holding a control character (CR, LF, NUL, DEL, C1) are refused before the `security` CLI runs, so a crafted name cannot inject a second command into `security -i`. `import` anchors the email check strictly (a trailing newline is no longer accepted, unlike claude-swap) and refuses whitespace or control characters in email and alias, emails over 254 bytes, aliases over 64 bytes and slots over 999999. Codex exports are written atomically (0600 temp file, then rename) like Claude exports; the log, the usage cache, lock files and session markers are created 0600 under 0700 directories.
- `purge` removes each account's retained `.prev` Keychain item as well as the current one; before, the `.prev` generation outlived the purge on macOS.
- `tycswap upgrade` installs `github.com/tyclab/tycswap/cmd/tycswap@latest`, and the update notice reads tycswap's GitHub releases; before, both pointed at the upstream project. A binary built from a checkout is told `git pull && make install` and nothing is installed. `update.ModulePath`, `update.Endpoint` and `update.ReleasesURL` are settable with `-ldflags -X`.
- **Breaking:** renamed to tycswap. The module is `github.com/tyclab/tycswap`, the binary `tycswap`, the store `~/.local/share/tycswap` (Linux/WSL, `$XDG_DATA_HOME/tycswap` when set) or `~/.tycswap` (macOS/Windows), the log `tycswap.log`, the macOS Keychain services `tycswap` and `tycswap-codex`, and exports are named `.tycswap`. There is no `cswap` alias and no fallback to the old store; `tycswap migrate [--dry-run] [--json]` copies an existing claude-swap store once and never changes it. The startup move of `~/.claude-swap-backup` is gone, and `purge` no longer removes that directory.
- `tycswap add --login [--switch]` runs `claude auth login` in a scratch profile and stores the second account without a logout; the live login stays untouched.
