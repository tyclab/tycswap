# Changelog

## Unreleased

- **Fixed:** on Windows, taking a Claude Code lock right after another process released it no longer fails with "Access is denied": a lock directory pending delete counts as held and is retried.
- **Fixed:** `status` and `list` report a busy store lock. On a roster that still needed the organization backfill, they read a store another tycswap process held as empty, showing the live account as "(not managed)" and listing no accounts (DESIGN A57).
- **Fixed:** on Windows, replacing a store file while another reader of it is open (the status-line rebuild reads `sequence.json` while a roster write replaces it) no longer fails with "Access is denied": the atomic rename is retried for about half a second.
- **Fixed:** `add --login` no longer passes `CLAUDE_SECURESTORAGE_CONFIG_DIR` to the login, which could store it into the live login's Keychain item or credential file, and its cleanup also deletes the scratch profile's API-key Keychain item that a managed `forceLoginMethod` of `console` creates. When `--slot` moves the live account or overwrites its record, `activeAccountNumber` follows it or is cleared instead of naming a deleted slot (DESIGN A56).
- **Fixed:** a switch holds Claude Code's storage-write lock (`.storage-write.lock` in the config home, or in `CLAUDE_SECURESTORAGE_CONFIG_DIR` when set, where the credential-refresh lock now follows too), so an MCP login Claude Code saves mid-switch is no longer lost or written back over the new account; Claude Code's credential-refresh lock is taken over only after 60 s (storage-write 15 s, config 10 s), not after 10 s while Claude Code may still hold it; and Ctrl-C releases the Claude Code locks the process holds instead of leaving them for Claude Code to wait out (DESIGN A55).
- **Added:** `statusline.json` in the store for Claude Code status lines: each account's label and last measurement (5h, 7d and per-model windows, integer epochs), keyed by `email|organizationUuid` as in `~/.claude.json`. Rebuilt whole after every switch, roster change and usage merge; it never holds a key or token, a failure to write it never fails an operation, and `tycswap migrate` does not copy another tool's. See "Status line integration" in the README (DESIGN A54).
- **Fixed:** on Windows, `add --login -- …` and `tycswap run -- …` run Claude Code installed by npm (`claude.cmd`) from a path with a space, such as a user profile named `First Last`, when an argument also holds a space. cmd.exe stripped the quotes off the command line and ran the path only up to its first space; tycswap now quotes the line for cmd.exe itself, for every claude and codex `.cmd` it starts.
- **Fixed:** with the tray app and a command logging at once, one no longer writes into the log file the other rotated away, and on Windows the open log no longer blocks its rotation or deleting the store. A shell pinned to a removed session profile is unpinned also when the store's path runs through a symlink or a Windows short name. The dashboard serves its script, stylesheet and icon with fixed content types, not the ones the Windows registry records.
- **Fixed:** the Windows tray icon comes back after Explorer restarts. Explorer recreates the taskbar empty and asks every program to add its icon again; the tray added its icon only at start, so after an Explorer restart it was gone until the app restarted, while the app kept running unseen. It now adds the icon again with its current tooltip and icon (DESIGN A52).
- **Fixed:** on Windows, a Ctrl-C while `tycswap app` or `tycswap app --remote` is starting, before its tray icon shows, ends it; the tray kept running and ignored every later Ctrl-C. When adding the icon again after an Explorer restart fails, the tray keeps the icon the taskbar may still show instead of destroying it (DESIGN A52).
- Complete the model-window controls on Auto and Settings: Off/All/Selected, stable drafts and focus, empty-selection Reset, and stale-state rejection across saves. Tray percentages now honor selected model names instead of counting every model window.
- `TYCSWAP_AUTO_MANAGED_BY` protects externally scheduled auto-switch: the dashboard server rejects hosted-engine starts and remembered resume, and dashboard/tray controls show the owner and disable startup.


- Fixed storage transaction isolation: Claude's lazy roster migration now takes the writer lock and re-reads after acquisition; Codex registry and snapshot writes reuse a lock only through an explicit transaction view, never because another goroutine holds it.
- `add --login` selects subscription mode and refuses `--console` before launch. Failed scratch-Keychain cleanup is reported and retried on the next login; shared Console keys and live credentials remain untouched.

The key was the last of eleven in the registry, so `tycswap config`, the TUI's Settings screen and the dashboard's Settings tab listed it at the bottom, eight rows below `autoswitch.modelThreshold`, the bar that applies only to the windows it names; it now sits between the 7d threshold and the model threshold. On the Settings tab it is a switch for every per-model window the accounts report (*Fable*) and *All models* instead of a text field to type names into; a name the saved value carries that no account reports keeps a switch of its own, ticked, so a save never drops it, and *Save* with nothing ticked resets the key. With no model window reported and no name saved, the row keeps the text field. The "limits ignored" warning's tooltip points at those switches (DESIGN A49).
- **Fixed:** Ctrl-C ends `tycswap web` and `tycswap app` with 0 and lets them clean up. The program-wide Ctrl-C handler, which prints `Operation cancelled` and exits 130 for every other command, received the signal beside the servers' own and won, so the app's remote token file stayed behind and an engine's Codex switch in flight was cut off; the two servers now claim the signal while they serve, their context ends the serve loop and their deferred work runs. v0.7.1's note said Ctrl-C already ended `tycswap web` with 0; only SIGTERM did (DESIGN A48).
- **Fixed:** `tycswap codex disable`, `enable` and `remove`, and the terminal dashboard's Codex disable and remove, hold the Codex store lock as a Codex switch does. They wrote through the store's own lock, which a process then skipped while another of its goroutines held the lock, and the usage refresh holds it around its network call: a remove in the terminal dashboard during a refresh of the same account deleted the slot, and the refresh then wrote the refreshed token back under the removed account's key, a live credential file for an account that no longer existed. Every Codex verb now waits up to 10 s for a holder, in this process or another, and refuses when the store stays busy; the browser dashboard's own wrapper around disable and remove is gone, since the switcher holds the lock for every caller (DESIGN A48).

A bare `tycswap` from a script or pipe is still the `no command given` usage error, and `tycswap menubar` now names `tycswap app` (DESIGN A40).

The icon shows the active account and its fullest window (`⟳` while auto-switch runs); the menu switches accounts in one click (more than ten in a submenu), adds the login Claude Code has, turns auto-switch on and off (naming each window's threshold), counts or ignores the per-model windows, registers start at login, checks for updates and opens the dashboard; notifications report auto-switch's moves and quarantines and an account reaching a window's threshold. A badge (a dot, or the count on macOS) means a newer tycswap or Claude Code waits; the tray installs it after asking and restarts itself after its own update. Auto-switch that was on when the app quit is on again when it starts (`autoSwitch` in `ui_prefs.json`). The tray shows the dashboard's state, Codex accounts and the Codex engine included (DESIGN A47). One app runs per machine (`app.lock`), and `tycswap purge` refuses while it runs. The icon is tycswap's octopus in the accent colour's shades (DESIGN A35–A44).

Checkout builds and go-installed binaries keep their own way, and a release binary a package manager installed (the Nix store, a Homebrew Cellar, Scoop, WindowsApps, or started through a symbolic link) is left to it, with a hint that names it (DESIGN A24, A36).

The account table lists them under a Codex heading after the Claude accounts, with their 5h and 7d windows, *Switch*, *Disable* / *Enable* and *Remove*, the terminal dashboard's actions on a Codex row; *+ Add current Codex login* stores the account the codex CLI is signed in with, and a switch that leaves codex sessions running names their PIDs. The Auto tab's Start runs the Codex engine beside the Claude one, built and ticking exactly as in `tycswap auto` (its bar is `autoswitch.codexThreshold`, or the 7d threshold when that is 0, fixed for the run; the slider leaves it), with a tile of its own and its switches and errors in the event log tagged `codex`. The state document's rows gain the Codex accounts (`provider` `codex`, key `codex:<n>`), `auto.codex` describes the Codex engine (null without Codex accounts), and an engine event carries `provider` only for a Codex tick, so the existing JSON is unchanged; the account routes take `codex:` keys for switch, disable, enable and remove, `POST /api/accounts/add` takes `{"provider": "codex"}`, and alias, move and swap stay Claude-only. `tycswap app` builds the same dashboard: its menu lists the Codex accounts under a Codex heading, a click switches one by its key (locally and from a remote tray) and names the codex sessions still running, a Codex auto-switch is notified as one, the auto-switch row names the Codex bar, and the resumed auto-switch starts both engines (DESIGN A47).
- An API-key account may carry a base URL: `tycswap add-token --base-url URL` (the TUI's and the dashboard's add-token forms have the field too) stores the key as that endpoint's, whatever it looks like, and a switch onto the account points Claude Code at it. Such a switch stores no key in Claude Code's credential store; it writes `env.ANTHROPIC_BASE_URL` and the key as `env.ANTHROPIC_AUTH_TOKEN` into Claude Code's `settings.json` and removes `env.ANTHROPIC_API_KEY` (which Claude Code would send to the endpoint as well), after recording what those keys held in `claude-settings.prev.json` in the backup root, and a switch onto any other account (`--force` and the fresh machine included) puts exactly that back and leaves every other key of the file as it is now. It warns, by name, when an `apiKeyHelper` in `settings.json` or `ANTHROPIC_API_KEY` in the environment would still send a second key. A switch that fails puts both files back. The approval prompt names the URL, `list` and `status` show the host, their `--json` rows and `export`/`import` carry `baseUrl`, and `purge` says when it deletes the record (DESIGN A46).
- Auto-switch judges each usage window against a threshold of its own: `autoswitch.fiveHourThreshold` (default 85) for the 5h window, `autoswitch.sevenDayThreshold` (97) for the 7d window and `autoswitch.modelThreshold` (95) for the per-model weekly windows `autoswitch.model` counts, each 50–100, where 100 means never move before that window is full. The 5h window bursts (parallel subagents can fill it between two polls), so its bar is the lowest; the weekly windows creep and can run close to full. The costliest window over its bar decides (the week, then a model's week, then the 5h window) and the switch names it (`axis` in `auto --json`, `(proactive, 5h)` in the line); a candidate is judged on that window, a spent week is never a target, `best` ranks by weekly headroom, and the poll cadence keys on the lowest bar in force. The TUI's `t` adjustment and the dashboard slider move the 7d bar; the TUI summary and the dashboard's Next best name every bar and mark a row at threshold when any window reached its own bar. The Codex engine keeps its single bar, the worse of its windows against `autoswitch.codexThreshold`, which now falls back to the 7d bar (97 by default, or the value an old `autoswitch.threshold` seeds) instead of the removed single threshold. **Breaking:** `autoswitch.threshold` and `tycswap auto --threshold` are replaced by the three settings and `--five-hour-threshold`, `--seven-day-threshold` and `--model-threshold`; a `settings.json` that still has `autoswitch.threshold` keeps working, its value seeds the 7d bar, and `config unset autoswitch.sevenDayThreshold` removes both keys (DESIGN A34).
- A switch onto an API-key account needs the user's approval, and auto-switch never makes one. Such a switch changes how Claude Code authenticates (a key billed per token instead of the subscription login), and a session that is already running keeps its old login until it is restarted. `switch <n>` onto an API-key account prints what changes and how many Claude Code sessions are running, then asks `[y/N]`; `--yes` (`-y`) answers for scripts, a run whose stdin is not a terminal is refused at once, every refusal exits 1, and `--json` switches only with `--yes`. The dashboard's *Switch* confirms first; the TUI and the dashboard's *Force switch* refuse and point at `tycswap switch <n>`. The switch itself refuses an API-key target without that approval, so no caller can skip it, and an approval is used up by the switch it was given for. After the switch the note says to restart the running sessions. Auto-switch, the bare `switch` rotation and `switch --strategy` rotate between subscription accounts only, even when all are at their limit, and leave an active API-key account alone. **Breaking:** `autoswitch.includeApiKeyAccounts` and `tycswap auto --include-api-key-accounts` / `--no-include-api-key-accounts` are removed; a `settings.json` that still has the key loads as if it did not, and `config set` refuses it as unknown (DESIGN A33).
- Auto-switch orders the accounts that qualify by earliest weekly renewal by default: `autoswitch.strategy` defaults to `soonest-reset` instead of `best`, so quota is spent where it comes back soonest and an account whose weekly window is about to renew is not left idle. A `settings.json` without the key (including a store copied from claude-swap) follows the new default; one that sets `best` keeps it, and `tycswap config set autoswitch.strategy best` restores the old order. `tycswap config`, the TUI's Settings screen, the dashboard's Settings tab and Guide show the new default (DESIGN A32).

- On macOS, a switch onto an API key keeps the key readable when an oversized MCP credential falls back from Keychain to the credentials file. If the managed-key fallback cannot be saved, the switch fails before replacing the original OAuth credential.
- On macOS, a switch onto an API-key account (also `--force`) that fails after storing the key in the Keychain, because `~/.claude.json` could not be updated, no longer leaves the key there. The switch rolls the credential back only after a write that succeeded, so nothing removed it: from a subscription login the key stayed in the Keychain beside the login, and from another API-key account it replaced that account's key while tycswap still recorded that account as active. The failed write now puts the Keychain item back as it was, the previous key or none; a previous key held in `primaryApiKey` alone goes into the item, so it stays live; and when the item cannot be put back, the error says the new key is still there. To know what to put back, the switch reads the item first; when that read keeps failing, the key goes to `~/.claude.json`, as when the Keychain cannot store it. A rollback onto an API key keeps the key it restores. Outside the Keychain such a failure already wrote nothing (DESIGN A29).
- An account at the limit of a window that resets more than an hour out no longer reads as `usage unavailable` from an hour after its last fetch until that reset. Such an account (for example an inactive one whose per-model weekly window is at 100% while `autoswitch.model` is `all`) was not polled again before the window reset, days later, while its measurement stopped being trusted after an hour: `list --json` and `status --json` reported `usageStatus: "unavailable"`, the dashboard showed *usage unavailable*, `list` printed the old numbers with an age note and did not refetch, and the auto-switch engine could not rank the account. An account at its limit is now polled again at least every 57 minutes until its reset (DESIGN A31).
- Accounts at their limit that one pass fetched together (the auto-switch engine's full refresh while the active account nears the threshold, or a read that found them all due or without a plan) no longer all fall due at the same moment 57 minutes later. The engine fetches one due candidate per tick, so all but the first read as untrusted for a tick or more past their due time, to the engine and to views that only read the store, such as `tycswap tui` while its auto-switch view is open. The park of an account at its limit now ends a random 0–10% early, 51 to 57 minutes after its fetch, so such accounts mostly fall due on different ticks; it never ends later, so the measurement is still trusted when its poll falls due (DESIGN A31).

A refused value shows its message without writing; a saved threshold moves the dashboard's bar tick. Builds with an injected version and checkout builds are unchanged.
- Security: a switch no longer logs the MCP servers out. Claude Code keeps its MCP server OAuth tokens in `~/.claude/.credentials.json` under `mcpOAuth`, keyed by server rather than by account; a switch (manual, `--force`, auto, or `add --login --switch`) now writes the target account's stored credential with the live `mcpOAuth` carried over it, and `add`, the switch-time backup, the unclaimed stash, the active refresh write-back and `export` store or ship the account part only, so MCP logins neither flip with the account, go stale in a backup, nor travel in an export. `trustedDeviceToken` stays with the account. Rollback still restores the exact pre-switch bytes.
- An API-key seat no longer loses its key or its MCP logins. On such a seat Claude Code writes `~/.claude/.credentials.json` holding only the MCP server logins when one is signed in to; tycswap read that file as the live OAuth login, so a switch away stored it in the API-key slot in place of the key, the switch back cleared the key and left no working credential, `status` and `list` showed the account as `no credentials`, and `add` stored the MCP data as a new subscription account. A credentials file or Keychain item holding nothing but seat-wide keys (or `{}`) is now no login: the managed key behind it is the live credential for the switch-time backup, `add`, `export`, `status` and `list`, and with no key behind it a switch away refuses as for an empty credential. A switch onto an API-key account keeps the seat-wide keys in the credentials file (or Keychain item) instead of deleting it, as Claude Code's own move onto an API key does. `mcpOAuthClientConfig`, the client secret an MCP server was added with (`claude mcp add --client-secret`), is seat-wide too: it is carried over every switch and left out of every stored or exported credential like `mcpOAuth`; a stored credential's own copy of either key is never written live, and `import` and the legacy keyring migration store the account part only (DESIGN A29).
- An API-key slot the switch-time backup had already emptied before that fix (it holds `{}`, or only the MCP server logins or client secrets, and its key survives in `.prev`) is no longer switched to. tycswap took the stored text for an OAuth login, wrote it live and cleared the managed key, so `switch`, `switch --force`, the rotation, the dashboard and the auto-switch engine reported success over a seat left with no working credential, and `export` shipped the `{}` as the account's credentials. A stored credential holding nothing but seat-wide keys now counts as no stored credential: `switch <n>` stops with `Account-<n> has no stored credentials` before the live login or the managed key is written, the rotation and the auto-switch engine skip the slot, and `export` leaves it out (DESIGN A30).
- A direct activation onto an API-key account (`switch <n> --force`, a fresh machine, or a live login no slot holds) no longer loses the key. It wrote back the copy of `~/.claude.json` it had read before writing the credential, which dropped what the key write had just stored there: `primaryApiKey` and the key's approval. Outside the macOS Keychain the seat was left with no credential while the switch reported success. In the other direction, a `--force` from a live API key onto a subscription account left the old key in `~/.claude.json`. The activation now reads the file again after the credential write, as the normal switch does (DESIGN A29).
- `list` no longer prints an empty "Running instances:" heading when the only live IDE lock has no workspace folders. Paths are shortened to `~` only when the home directory is followed by a separator (`/home/xavier` is no longer `~avier` for home `/home/x`); Windows compares case-insensitively.
- `tycswap migrate` resumes an interrupted copy: a rerun copies what is missing, verifies byte for byte what is there, removes a leftover temp file, and refuses only when a path differs from the old store or is not from it. A rerun after a complete copy is a verified no-op.
- Hardening: atomic writers fsync the temp file and the directory, and config backups are written atomically. `settings.json` and `mappings.json` updates hold a lock (`.settings.lock`, `.mappings.lock`) so concurrent commands no longer lose each other's change. `go.mod` pins `toolchain go1.25.14`; `golang.org/x/mod` is raised to v0.40.0 (GO-2026-6179, GO-2026-6180; tycswap does not call the affected code); `make vuln` runs govulncheck.
- Security: strings from exports, APIs and other tools' files (emails, aliases, organization/workspace names, IDE paths) are printed without C0/C1/ESC control characters in `list`, `status`, the dashboard and the Codex commands; `--json` output carries them as stored. `env --shell pwsh` doubles U+2018–U+201B as well as `'`. `add --login` scrubs the auth override variables like `run`/`env`. `add-token` warns when the token is given on the command line, and the docs show the prompt and `-` instead. On Windows, `run` and `add --login` refuse cmd.exe metacharacters in arguments when `claude` is a `.cmd`/`.bat` shim.
- Security: every command refuses a store root not owned by the effective user, naming the path, and makes a root writable by group/other 0700 before it runs; when the mode does not change (a filesystem without POSIX modes, such as a Windows drive under WSL), it warns once on stderr and continues (POSIX). The store lock is opened without following symlinks and without truncation (0600). A stale Claude Code lock directory is broken by rename-then-remove with an age recheck, so two waiters can no longer both hold it; a lock found fresh after the rename is put back without replacing one a third waiter took meanwhile (`renameat2` with `RENAME_NOREPLACE` on Linux). Directories tycswap creates (credentials, `~/.claude`, export parents, lock dirs) are 0700 instead of 0777 before umask. The Claude and Codex HTTP clients no longer follow redirects (a 307 would have re-posted the refresh token); the Claude client caps success bodies at 1 MiB, requires a non-empty string `access_token` and 0 < `expires_in` < 1e7, and logs only the error code of a failed refresh, never the body.
- Security: an inactive account's token refresh (`list`, `status`, dashboard) now takes the store lock before the request, re-checks that the slot is still inactive with no live session, re-reads the backup, and refreshes only when its refresh token is unchanged, as the Codex side does; a concurrent switch or refresh can no longer be overwritten or have its token consumed. `run`/`env` no longer refresh a backup that shares its refresh token with the live login (slot is the current account, or the fingerprints match). `codex login` stores the live auth into its slot before codex replaces it.
- Security: `add` and `add --login` refuse a login whose email cannot name a file, since the email names the account's backup files (`a/../../../x` would name files outside the store): it must hold one `@` between a non-empty local part and domain, at most 254 bytes, and no whitespace, control character, `/`, `\` or `< > : " | ? *`; every real address, an apostrophe or a non-ASCII letter included, is accepted and stored under its raw name. `purge` applies the same check to every `sequence.json` email before it builds a path from one and refuses with the slot named. `import` keeps claude-swap's stricter address pattern for export files. `codex import` validates every row first (email, alias, accountKey) and refuses the file on a bad one; both imports store display fields without control characters.
- `tycswap migrate` copies a macOS Keychain item too large for the `security` command's stdin line (over about 2 KB, as the old tool stored through the command line) to the file tycswap reads for it instead of failing: `credentials/.creds-<n>-<email>.enc[.prev]`, `codex/credentials/<key>.json` or the session profile's `.credentials.json`, mode 0600; the report names the file. The legacy keyring migration does the same with the `.enc` file instead of retrying on every launch.
- Security: on macOS a Claude credential too large for `security -i`'s stdin line (over about 2 KB, reachable with `mcpOAuth` tokens) was passed to `security` on its command line, where `ps` shows it to every local user. The Keychain wrapper now refuses such a payload and the credential is stored in its 0600 file instead (backup `.enc`, `.enc.prev`, or the live `.credentials.json`); the Keychain stays in use for everything else.
- Security: `import` keeps only each account's `oauthAccount` from an export's `config` (a `--full` export included), so an export carrying `mcpServers`, allowed tools or hooks can no longer configure commands on the importing machine; an account without `oauthAccount` is refused. Members are matched exactly and the stored credentials are the bytes that were validated (a `CREDENTIALS` twin used to be stored instead); input over 8 MiB is refused. A switch with no live `~/.claude.json` writes `{"oauthAccount": …}` alone instead of the whole stored config, and a live `~/.claude.json` that exists but does not parse is an error for a switch and for `add-token` instead of being replaced by the few keys tycswap sets.
- `tycswap web [--port N] [--no-open] [--interval SECONDS] [--debug]` serves a browser dashboard on 127.0.0.1: Dashboard (accounts and their actions), Auto (a hosted auto-switch engine with its settings, Next best, quarantine and event log), and Sessions (running Claude Code sessions, including `run`/`env` profiles, with Stop). The printed URL carries a one-time token; redeeming it sets the port-scoped session cookie and hands the page its CSRF token in the redirect's URL fragment, so the browser tab that opened the URL is the only one that can drive the page (a reload keeps it, a new tab needs a fresh URL). Every API call needs cookie and token, mutations a same-origin request, and a foreign Host gets 421. Stop signals a session only after the process start time matches its session file. On Linux and macOS the launch token reaches the browser through a 0600 redirect page in a private directory, never a command line. Export and import stay on the command line.
- The auto-switch engine can retarget its model windows while it runs (`Engine.ApplyModels`), so the dashboard's *Count model limits* applies at once.
- Internal: JSON account listings carry `tokenStatus` when token status is asked for; it was ignored before. Build-time branding vars in `internal/brand` (see `docs/reference.md`, BUILD-TIME BRANDING).
- Security: Keychain service and account names holding a control character (CR, LF, NUL, DEL, C1) are refused before the `security` CLI runs, so a crafted name cannot inject a second command into `security -i`. `import` anchors the email check strictly (a trailing newline is no longer accepted, unlike claude-swap) and refuses whitespace or control characters in email and alias, emails over 254 bytes, aliases over 64 bytes and slots over 999999. Codex exports are written atomically (0600 temp file, then rename) like Claude exports; the log, the usage cache, lock files and session markers are created 0600 under 0700 directories.
- `purge` removes each account's retained `.prev` Keychain item as well as the current one; before, the `.prev` generation outlived the purge on macOS.
- `tycswap upgrade` installs `github.com/tyclab/tycswap/cmd/tycswap@latest`, and the update notice reads tycswap's GitHub releases; before, both pointed at the upstream project. A binary built from a checkout is told `git pull && make install` and nothing is installed. `update.ModulePath`, `update.Endpoint` and `update.ReleasesURL` are settable with `-ldflags -X`.
- **Breaking:** renamed to tycswap. The module is `github.com/tyclab/tycswap`, the binary `tycswap`, the store `~/.local/share/tycswap` (Linux/WSL, `$XDG_DATA_HOME/tycswap` when set) or `~/.tycswap` (macOS/Windows), the log `tycswap.log`, the macOS Keychain services `tycswap` and `tycswap-codex`, and exports are named `.tycswap`. There is no `cswap` alias and no fallback to the old store; `tycswap migrate [--dry-run] [--json]` copies an existing claude-swap store once and never changes it. The startup move of `~/.claude-swap-backup` is gone, and `purge` no longer removes that directory.
- `tycswap add --login [--switch]` runs `claude auth login` in a scratch profile and stores the second account without a logout; the live login stays untouched.
