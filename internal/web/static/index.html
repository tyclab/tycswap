        What this is
        
        
        Claude Code signs in as one account at a time, and every account has usage windows that run out. {{.Name}} keeps several Claude accounts on this machine, shows how much room each of them has left, and swaps the one Claude Code uses: by hand with one click, or automatically before you hit a wall. It does the same for Codex (ChatGPT) accounts from the command line.
        
        
        With your accounts it only reads their usage and refreshes a stored login's token; the update check reads public release information and sends nothing about you. Switching only rewrites Claude Code's local credential and config files, exactly as signing out and back in would.
        
      
        

      
        
        
        The five things to understand
        
        
        
          
        Account / slot
        
          
        Each stored login is an account in a numbered slot (#1, #2, …). You can give a slot an alias (work, spare) and use number, alias or email interchangeably everywhere.
        
          
        Active account
        
          
        The one Claude Code is using right now. The header always shows it with its three meters. Changing it is what “switching” means.
        
          
        Windows: 5h, 7d, model
        
          
        Anthropic limits each account per rolling 5-hour window and per 7-day window, and some plans add a per-model weekly window. A meter shows the share used; the small text underneath says when that window resets. green = plenty left, amber = getting close, red = at the limit.
        
          
        At limit / eligible
        
          
        An account is at limit when any counted window is at 100 %. It is eligible for rotation when it is enabled, has stored credentials and is not the active one; those are the accounts Auto mode may pick.
        
          
        The thresholds
        
          
        One bar per window, at which Auto mode considers that window full and looks for another account: autoswitch.fiveHourThreshold (85 % by default), autoswitch.sevenDayThreshold (97 %) and, for the counted model windows, autoswitch.modelThreshold (95 %). Each window is judged against its own bar. Set them on the Settings tab; the Auto tab's slider moves the 7d bar for the running engine only.
        
        
        
      
        

      
        
        
        Getting started in 3 minutes
        
        
          
          
        1. Sign in to Claude Code with your first account: start claude, type /login and sign in in the browser.
          2. 
          
        2. Store it here. Dashboard → Add current login. The account appears as #1. Give it an alias from its row menu if you like.
          3. 
          
        3. Repeat for every account: in Claude Code type /login and sign in with the next one, then Add current login again. Each becomes the next slot. Never /logout in between: logging out ends the login you just stored, and that account stops working. From a terminal, {{.Name}} add --login does the same without touching the live login: it signs in with the next account in the browser and stores it as the next slot; add --switch to make it active at once.
          4. 
          
        4. Pick the active one from the Dashboard (the row's Switch) or turn on Auto mode and let it decide.
          5. 
          
        5. Restart running Claude Code sessions after a switch (claude --continue picks up where you were). The Sessions tab shows what is running.
          6. 
        
        
        
        Have a setup token or an API key instead of a browser login? Add token… here, or {{.Name}} add-token in a terminal. API-key accounts have no usage windows, and neither Auto mode nor a rotation ever moves onto one: you switch to one by hand and confirm. An API-key account may carry a base URL (the field in Add token…, or {{.Name}} add-token --base-url): a switch to it writes the endpoint and the key into Claude Code's settings.json as env.ANTHROPIC_BASE_URL and env.ANTHROPIC_AUTH_TOKEN and removes env.ANTHROPIC_API_KEY, and a switch to any other account puts back exactly what those keys held. A running Claude Code can take the endpoint up at once, but keeps it after a switch away until it is restarted.
        
      
        

      
        
        
        Switching by hand
        
        
          
          
        • Switch in an account's row makes that account active at once, whatever its windows say. Force switch in the row menu skips the backup of the current login first. A switch onto an API-key account asks first: it changes how Claude Code authenticates, and running sessions keep their old login until restarted. Force switch does not ask that and is refused for an API-key account.
          • 
          
        • Best (the strategy control on the Dashboard) switches to the account with the most headroom; Next available goes to the next slot in order that is not at limit. Neither ever picks a disabled account or an API-key account.
          • 
          
        • Disable an account to keep it stored but out of every rotation; a shared account you only want on demand, say. Enable brings it back.
          • 
          
        • Move / Swap renumbers slots; Remove deletes the stored copy (your Claude login itself is untouched).
          • 
        
        
        
        Windows come back on their own: a 5-hour window at 100 % is usable again five hours after it filled, which is what the countdown under each meter tells you.
        
      
        

      
        
        
        Auto mode
        
        
        The engine polls every account's usage, and when one of the active account's windows crosses its own bar it switches to the best candidate and logs why, naming the window (5h, 7d or model). Start and stop it on the Auto tab; the tab badge shows a dot while it runs. The engine here runs inside {{.Name}} web; {{.Name}} auto runs the same engine in a terminal. On a machine with Codex accounts both run the Codex engine beside it, which rotates Codex accounts on a bar of its own.
        
        
        Settings that matter
        
        
        
          
        5h threshold
        autoswitch.fiveHourThreshold, 85 % by default: the lowest of the three bars, because this window bursts. A fan-out of parallel subagents can take it from 85 % to full between two polls, and hitting 100 % stops you mid-task. Raise it only if you work in small, predictable steps; lower it (or poll more often) if you run wide fan-outs.
        
          
        7d threshold
        autoswitch.sevenDayThreshold, 97 % by default: the 7-day window is the account's whole budget, and it creeps, so it can be squeezed nearly full before moving. This is the bar the slider and the TUI's ± keys move. A settings file that still has the old single autoswitch.threshold seeds this bar.
        
          
        Model threshold
        autoswitch.modelThreshold, 95 % by default: the bar for a per-model weekly window, weekly too, so also high. It applies only to the windows Count model limits counts. A bar of 100 means "never move on this window before it is full", for any of the three.
        
          
        Strategy
        autoswitch.strategy: soonest-reset (the default) prefers the account whose weekly window renews first, so several accounts are used evenly and none sits idle on a window that is about to renew; best takes the account with the most headroom right now.
        
          
        Count model limits
        autoswitch.model: empty counts 5h and 7d only; all, or a comma-separated list of model names, also counts those per-model weekly windows, so an account at 100 % of a model's week is skipped even if its 5h/7d meters are low. The Auto tab's switch sets all or clears it.
        
          
        Hysteresis, cooldown
        autoswitch.hysteresisPct: a target must beat the active account by this much, so two accounts at the same level do not flap. autoswitch.cooldownSeconds: the least time between two proactive switches.
        
          
        API-key accounts
        Auto-switch never moves onto, or off, an API-key account by itself. That is a change of how Claude Code authenticates, billed per token, and a session that is already running keeps its old login until you restart it, so only you can decide to make it. Switching to one by hand asks first. The header says so in red while one is active.
        
          
        Dry run
        Starts the engine so it logs what it would do without switching. Good for a first day.
        
        
        
        
        Quarantine
        
        
        An account whose credentials stop working (expired refresh token, re-login required) is quarantined: the engine stops trying it and lists the reason. Run {{.Name}} add --login in a terminal and sign in as that account to refresh it; the live login is untouched.
        
        
        The Next best panel shows the engine's current ranking with the reason for every account, so a surprising choice is never a mystery.
        
      
        

      
        
        
        Settings
        
        
        The Settings tab lists every key of settings.json with its type, range, default and current value, and saves or resets one key at a time; it is {{.Name}} config in the browser. Every key is an autoswitch.* key today: the three thresholds, the poll interval, the cooldown, the hysteresis, the strategy, the model windows, how many failed polls make an account unhealthy, and the Codex engine's own switch and threshold.
        
        
        A saved value is validated like config set (an out-of-range number is refused and nothing is written), and every row says when it takes effect. An auto-switch engine reads the settings when it starts (here, in {{.Name}} tui or in {{.Name}} auto), so a running one keeps what it started with; only autoswitch.model reaches a running engine on this page at once. The Codex keys are read when this page's engine or {{.Name}} auto starts.
        
      
        

      
        
        
        Sessions
        
        
        Every running Claude Code process on this machine, grouped by project directory, with its state (idle, busy, waiting for you), the IDE it belongs to, and the slot it runs as when it was started with {{.Name}} run or {{.Name}} env. Use it to see what a switch would interrupt, and Stop a session you forgot about. A running session keeps its current account until it is restarted; claude --continue resumes it.
        
      
        

      
        
        
        Updates
        
        
        The Dashboard checks for two updates when it starts and every six hours: a newer {{.Name}} release, and a newer Claude Code from the installer Claude Code was set up with (its native installer, npm, Homebrew or WinGet). The header shows a count while something waits; the card installs each one after you confirm, and shows what the installer printed. {{.Name}} web keeps running the old version until you start it again; running Claude Code sessions keep theirs until you restart them. A build from a checkout, or one installed outside a Go bin directory, is told how to upgrade instead.
        
      
        

      
        
        
        Codex accounts
        
        
        {{.Name}} switches Codex (ChatGPT) accounts too, under {{.Name}} codex: list, status, switch, add, login, alias, export and import. The terminal dashboard ({{.Name}} tui) shows them beside the Claude accounts, and {{.Name}} auto rotates them when autoswitch.codexEnabled is on (its own bar is autoswitch.codexThreshold; 0 means the Claude 7d threshold). On this page the Codex accounts are listed under their own heading after the Claude ones, with Switch, Disable / Enable and Remove; + Add current Codex login stores the account the codex CLI is signed in with, and the Auto tab's Start runs the Codex engine beside the Claude one, with its own tile and its ticks in the event log.

        When something looks wrong
        
        
        A switch happened but Claude Code still uses the old account
        Running sessions keep the credentials they started with. Restart them (claude --continue). The Sessions tab lists what is still running.
        
        
        Claude Code ignores the stored login altogether
        An ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, CLAUDE_CODE_OAUTH_TOKEN or ANTHROPIC_BASE_URL in the environment, or in the env block of Claude Code's settings.json, takes the place of the login. The Dashboard says so above the accounts when it sees one; unset the variable or remove the key.
        
        
        An account says “re-login needed” or “token expired”
        Its refresh token was revoked or expired. Run {{.Name}} add --login in a terminal and sign in as that account; the slot keeps its number and alias, and the live login is untouched. If it is the live account, signing in again in Claude Code and Add current login does the same.
        
        
        “Usage unavailable”
        The last usage read failed or is stale (offline, or the usage endpoint hiccuped). The meters keep the last good values; they refresh on the next poll.
        
        
        Auto mode switched to an account I did not expect
        Open the Auto tab: Next best shows the ranking and reasons at the time, and the event log records every decision. Usually the answer is a per-model window: turn on Count model limits if you care about a model's weekly headroom.
        
        
        “Not switchable” on an account
        Its stored credential or config backup is missing, typically after Claude Code changed its file layout. Re-add the account.
        
        
        The Updates card says it could not check
        The release endpoint or Claude Code's source could not be read (offline, a proxy, a rate limit). What the last successful check found still shows, and Check now asks again. {{.Name}} upgrade in a terminal says the same for this program.
        
        
        The dashboard lost its connection
        The dashboard only ever listens on this machine (127.0.0.1). If the process was stopped, run {{.Name}} web again and open the URL it prints: the old page's tokens are dead, so the page says “session ended” rather than retrying.
        
      
        

      
        
        
        Where your data lives
        
        
          
          
        • Accounts are stored under your user profile: ~/.local/share/{{.Name}} on Linux and WSL ($XDG_DATA_HOME/{{.Name}} when that is set), ~/.{{.Name}} on macOS and Windows. Each account's credential goes to the macOS Keychain where available, otherwise to a file only you can read; the roster (sequence.json), the config snapshots, settings.json and the usage cache sit next to them, and {{.Name}} config path prints where.
          • 
          
        • The dashboard binds to 127.0.0.1 only and requires the per-launch secrets its URL carries; nothing is reachable from the network, and no credential ever leaves the process.
          • 
          
        • Usage numbers come from the usage endpoint of each stored account; nothing about your conversations is read or sent anywhere.
          • 
          
        • Exports ({{.Name}} export) hold live credentials in plain text: treat the file like a password.
          • 
          
        • Nothing is reported anywhere. There is no telemetry; the update check reads a release endpoint and Claude Code's installer source, and sends nothing but the request.
