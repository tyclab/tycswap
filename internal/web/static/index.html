      What this is
      
        
      Claude Code signs in as one account at a time, and every account has usage windows that run out. {{.Name}} keeps several Claude accounts on this machine, shows how much room each of them has left, and swaps the one Claude Code uses: by hand with one click, or automatically before you hit a wall. It does the same for Codex (ChatGPT) accounts from the command line.
      
        
      With your accounts it only reads their usage and refreshes a stored login's token; the update check reads public release information and sends nothing about you. Switching only rewrites Claude Code's local credential and config files, exactly as signing out and back in would.
      
      
      

      
      
        
      The five things to understand
      
        
      
          
      Account / slot
      
          
      Each stored login is an account in a numbered slot (#1, #2, …). You can give a slot an alias (work, spare) and use number, alias or email interchangeably everywhere.
      
          
      Active account
      
          
      The one Claude Code is using right now. The header always shows it with its three meters. Changing it is what “switching” means.
      
          
      Windows: 5h, 7d, model
      
          
      Anthropic limits each account per rolling 5-hour window and per 7-day window, and some plans add a per-model weekly window. A meter shows the share used; the small text underneath says when that window resets. green = plenty left, amber = getting close, red = at the limit. A window Anthropic does not report for an account (a verified Ultra login has no 5-hour limit) shows a dash, and the 5-hour column is left out while no listed account has one. The plan chip next to oauth is the plan Claude Code reports for that login.
      
          
      At limit / eligible
      
          
      An account is at limit when any counted window is at 100 %. It is eligible for rotation when it is enabled, has stored credentials and is not the active one; those are the accounts Auto mode may pick.
      
          
      The thresholds
      
          
      One bar per window, at which Auto mode considers that window full and looks for another account: 5-hour threshold (autoswitch.fiveHourThreshold, 85 % by default), Weekly threshold (autoswitch.sevenDayThreshold, 97 %) and, for the counted model windows, Model threshold (autoswitch.modelThreshold, 95 %). Each window is judged against its own bar. Set them on the Settings tab.
      
        
      
      
      

      
      
        
      Getting started in 3 minutes
      
        
        
          
      1. Choose Add account… here or in the tray. Guided setup opens in a terminal.
        2. 
          
      2. Choose Claude or Codex and complete browser sign-in. The account is saved automatically.
        3. 
          
      3. Repeat to add another account. Claude sign-in leaves your current login active. Codex sign-in saves the outgoing login, then changes the current account.
        4. 
          
      4. Pick the active one from the Dashboard (the row's Switch) or turn on Auto mode and let it decide.
        5. 
          
      5. Restart running Claude Code sessions after a switch (claude --continue picks up where you were). The Sessions tab shows what is running.
        6. 
        
      
        
      Have a setup token or an API key instead of a browser login? Add token… here, or {{.Name}} add-token in a terminal. API-key accounts have no usage windows, and neither Auto mode nor a rotation ever moves onto one: you switch to one by hand and confirm. An API-key account may carry a base URL (the field in Add token…, or {{.Name}} add-token --base-url): a switch to it writes the endpoint and the key into Claude Code's settings.json as env.ANTHROPIC_BASE_URL and env.ANTHROPIC_AUTH_TOKEN and removes env.ANTHROPIC_API_KEY, and a switch to any other account puts back exactly what those keys held. A running Claude Code can take the endpoint up at once, but keeps it after a switch away until it is restarted.
      
      
      

      
      
        
      Switching by hand
      
        
        
          
      • Switch in an account's row makes that account active at once, whatever its windows say. Force switch in the row menu skips the backup of the current login first. A switch onto an API-key account asks first: it changes how Claude Code authenticates, and running sessions keep their old login until restarted. Force switch does not ask that and is refused for an API-key account.
        • 
          
      • Best (the strategy control on the Dashboard) switches to the account with the most headroom; Next available goes to the next slot in order that is not at limit. Neither ever picks a disabled account or an API-key account.
        • 
          
      • Disable an account to keep it stored but out of every rotation; a shared account you only want on demand, say. Enable brings it back.
        • 
          
      • Move / Swap renumbers slots; Remove deletes the stored copy (your Claude login itself is untouched).
        • 
        
      
        
      Windows come back on their own: a 5-hour window at 100 % is usable again five hours after it filled, which is what the countdown under each meter tells you.
      
      
      

      
      
        
      Auto mode
      
        
      Auto-switch checks every account's usage, and when one of the active account's windows crosses its own bar it switches to the best candidate, naming the window (5h, 7d or model) in the log. The Auto-switch switch on the Auto tab turns it on and off (it is autoswitch.enabled, the same switch as the tray's and {{.Name}} auto on|off); the tab badge says on or off. The line under the heading says who checks: a scheduler that runs {{.Name}} auto --once and when it last checked, or this dashboard and how often. On a machine with Codex accounts every check also rotates Codex accounts, on a bar of their own.
      
        
      Counting now says which windows auto-switch counts and why: it follows the models your live sessions run. No setting chooses them.
      
        
      Settings that matter
      
        
      
          
      5-hour threshold
      autoswitch.fiveHourThreshold, 85 % by default: the lowest of the three bars, because this window bursts. A fan-out of parallel subagents can take it from 85 % to full between two checks, and hitting 100 % stops you mid-task. Raise it only if you work in small, predictable steps; lower it (or check more often) if you run wide fan-outs.
      
          
      Weekly threshold
      autoswitch.sevenDayThreshold, 97 % by default: the 7-day window is the account's whole budget, and it creeps, so it can be squeezed nearly full before moving. A settings file that still has the old single autoswitch.threshold seeds this bar.
      
          
      Model limits
      Each check counts the model windows of the models the live default sessions run, while some usable account is below its bars on them, and 5h and 7d otherwise. No setting or flag chooses them.
      
          
      Model threshold
      autoswitch.modelThreshold, 95 % by default: the bar for every per-model weekly window session following counts. A bar of 100 means "never move on this window before it is full", for any of the three.
      
          
      Account order
      autoswitch.strategy: soonest-reset (the default) prefers the account whose weekly window renews first, so several accounts are used evenly and none sits idle on a window that is about to renew; best takes the account with the most headroom right now.
      
          
      Minimum improvement, Switch cooldown
      autoswitch.hysteresisPct: a target must beat the active account by this much, so two accounts at the same level do not flap. autoswitch.cooldownSeconds: the least time between two proactive switches.
      
          
      API-key accounts
      Auto-switch never moves onto, or off, an API-key account by itself. That is a change of how Claude Code authenticates, billed per token, and a session that is already running keeps its old login until you restart it, so only you can decide to make it. Switching to one by hand asks first. The header says so in red while one is active.
      
          
      Dry run
      {{.Name}} auto --dry-run in a terminal decides and prints what it would do without switching.
      
        
      
        
      Quarantine
      
        
      An account whose credentials stop working (expired refresh token, re-login required) is quarantined: auto-switch stops trying it and lists the reason. Choose Add account… and sign in as that Claude account to refresh it; the live login is untouched.
      
        
      The Next best panel compares weekly, counted model-weekly, then 5-hour usage, with lower usage first. Soonest-reset mode keeps reset time first within each availability tier. Full accounts stay below usable ones; those whose counted full windows all reset within five hours lead the blocked group and are marked “at limit · resets <5h”. Model limits affect ranking only when counted. Each row shows why it is available or blocked.
      
      
      

      
      
        
      Settings
      
        
      The Settings tab lists the keys of settings.json with their type, range, default and current value, and saves or resets one key at a time; it is {{.Name}} config in the browser. Every key is an autoswitch.* key today: the three thresholds, the poll interval, the switch cooldown, the minimum improvement, the account order, how many failed polls make an account unhealthy, and Codex auto-switch with its own threshold. Poll interval is listed only while this dashboard runs the checks: a scheduler's auto --once never reads it.
      
        
      A saved value is validated like config set (an out-of-range number is refused and nothing is written), and every row says when it takes effect. A scheduler's next check reads the saved settings; an engine hosted in {{.Name}} web, {{.Name}} tui or {{.Name}} auto reads them when it starts and keeps them while it runs, except Auto-switch itself, which every check reads.
      
      
      

      
      
        
      Sessions
      
        
      The session list shows each Claude conversation's project and state. Every session runs on the default login, and tycswap moves that login by itself: each session's status line tells it the model the session runs, so while a Fable session runs the login stays on an account that can run Fable, and while none does, Fable-capable accounts are kept for Fable work. Subagents run on their session's login.
      
        
      The Windows tray opens an account table. Each percentage names its limit; 100% in Fable does not mean the shared weekly limit is full. Focus a row for reset times and freshness, or click a column to sort. The tray's Auto-switch toggle and the Auto tab's switch are the same setting. Click Weekly, 5-hour or a model limit to sort; click again to reverse. Next best restores availability ordering. Display sorting does not change automatic rotation.
      
        
      Session groups are retired. A former group hands its account back once its last session exits, and its conversations are copied into the default profile, so claude --resume continues them.
      
      
      

      
      
        
      Updates
      
        
      The Dashboard checks for two updates when it starts and every six hours: a newer {{.Name}} release, and a newer Claude Code from the installer Claude Code was set up with (its native installer, npm, Homebrew or WinGet). The header shows a count while something waits; the card installs each one after you confirm, and shows what the installer printed. {{.Name}} web keeps running the old version until you start it again; running Claude Code sessions keep theirs until you restart them. A build from a checkout, or one installed outside a Go bin directory, is told how to upgrade instead.
      
      
      

      
      
        
      Codex accounts
      
        
      {{.Name}} switches Codex (ChatGPT) accounts too, under {{.Name}} codex: list, status, switch, add, login, alias, export and import. The terminal dashboard ({{.Name}} tui) shows them beside the Claude accounts, and auto-switch rotates them wherever it runs when Codex auto-switch (autoswitch.codexEnabled) is on; its own bar is Codex threshold (autoswitch.codexThreshold; 0 = same as the weekly threshold). On this page the Codex accounts are listed under their own heading after the Claude ones, with Switch, Disable / Enable and Remove; + Add current Codex login stores the account the codex CLI is signed in with, and the Auto tab shows Codex auto-switch in its own tile.

      When something looks wrong
      
        
      A switch happened but Claude Code still uses the old account
      A switch reaches running sessions on their next request; a session started as another account with {{.Name}} run keeps its own login. Check that session's profile and any authentication overrides before restarting it.
      
        
      Claude Code ignores the stored login altogether
      An ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, CLAUDE_CODE_OAUTH_TOKEN or ANTHROPIC_BASE_URL in the environment, or in the env block of Claude Code's settings.json, takes the place of the login. The Dashboard says so above the accounts when it sees one; unset the variable or remove the key.
      
        
      An account says “re-login needed” or “token expired”
      Its refresh token was revoked or expired. Choose Add account… and sign in as that Claude account; its slot and alias stay the same. If it is the live account, signing in again in Claude Code and Add current login does the same.
      
        
      “Usage unavailable”
      The last usage read failed or is stale (offline, or the usage endpoint hiccuped). The meters keep the last good values; they refresh on the next poll.
      
        
      Auto mode switched to an account I did not expect
      Open the Auto tab: Counting now says which windows are counted and Next best shows candidates and their limits; a scheduler's journal (or the terminal running {{.Name}} auto) prints each check's decision. Usually the answer is a per-model window: one counts only while a live session runs that model and some usable account can serve it.
      
        
      “Not switchable” on an account
      Its stored credential or config backup is missing, typically after Claude Code changed its file layout. Re-add the account.
      
        
      The Updates card says it could not check
      The release endpoint or Claude Code's source could not be read (offline, a proxy, a rate limit). What the last successful check found still shows, and Check now asks again. {{.Name}} upgrade in a terminal says the same for this program.
      
        
      The dashboard lost its connection
      The dashboard only ever listens on this machine (127.0.0.1). If the process was stopped, run {{.Name}} web again and open the URL it prints: the old page's tokens are dead, so the page says “session ended” rather than retrying.
      
        
      macOS refuses to run a downloaded release (“cannot be opened”)
      The release binaries are not code-signed, so macOS quarantines one downloaded with a browser. xattr -d com.apple.quarantine {{.Name}} lifts it; downloading with curl -LO, go install and {{.Name}} upgrade avoid it.
      
      
      

      
      
        
      Where your data lives
      
        
        
          
      • Accounts are stored under your user profile: ~/.local/share/{{.Name}} on Linux and WSL ($XDG_DATA_HOME/{{.Name}} when that is set), ~/.{{.Name}} on macOS and Windows. Each account's credential goes to the macOS Keychain where available, otherwise to a file only you can read; the roster (sequence.json), the config snapshots, settings.json and the usage cache sit next to them, and {{.Name}} config path prints where.
        • 
          
      • The dashboard binds to 127.0.0.1 only and requires the per-launch secrets its URL carries; nothing is reachable from the network, and no credential ever leaves the process.
        • 
          
      • Usage numbers come from the usage endpoint of each stored account.
        • 
          
      • Exports ({{.Name}} export) hold live credentials in plain text: treat the file like a password.
        • 
          
      • Nothing is reported anywhere. There is no telemetry; the update check reads a release endpoint and Claude Code's installer source, and sends nothing but the request.
